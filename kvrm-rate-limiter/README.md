# KVRM Rate Limiter

A neural network-based rate limiting system that learns nuanced throttling decisions from context, replacing brittle rule-based systems with adaptive, intelligent rate limiting.

## Why KVRM for Rate Limiting?

Traditional rate limiters use simple algorithms (token bucket, sliding window) with hard-coded rules. They fail because:

1. **False Positives**: Legitimate users get blocked during normal usage spikes
2. **False Negatives**: Sophisticated abuse patterns slip through simple counters
3. **Configuration Nightmare**: Dozens of parameters that interact in complex ways
4. **One Size Fits All**: Same rules apply to premium users and free-tier, API calls and web requests
5. **Static Rules**: Can't adapt to new abuse patterns without code changes

**KVRM Rate Limiter** learns the *judgment* behind rate limiting decisions:
- Considers user history, tier, request patterns, system load, and behavioral signals
- Outputs nuanced decisions (soft throttle, hard block, warning, allow with monitoring)
- Generalizes to novel situations without explicit rules
- ~3-5MB model with microsecond inference

## Quick Start

```bash
# Generate training data
python data/generator.py --samples 100000 --output data/train.jsonl

# Train the model
python scripts/train.py --data data/train.jsonl --epochs 50

# Evaluate against baseline
python scripts/evaluate.py --model models/best.pt --baseline token_bucket

# Benchmark inference latency
python scripts/benchmark.py --model models/best.pt --iterations 10000
```

## Training Data Generation

Training data is generated by simulating:

1. **Normal Users**: Various tiers with realistic usage patterns
2. **Burst Patterns**: Legitimate spikes (product launch, viral content)
3. **Abuse Patterns**: Scrapers, credential stuffing, DDoS attempts
4. **Edge Cases**: New premium users, system overload, unusual timing

Labels are generated using expert rules initially, then refined with outcome data (user complaints, detected abuse, revenue impact).
